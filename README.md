# Focus Pulse — обратная связь фокус-группы МП

Бот читает до 5 чатов фокус-группы мобильного приложения. Он обезличивает данные клиентов, отделяет баги, пожелания, UX и вопросы от шума и выводит их на дашборд. Там админ принимает обращения, ставит сроки, отмечает устранение и получает текст задачи для Jira.

Стек — как у QuestionsNBU_bot: aiogram, Claude API, Google Sheets, Railway, GitHub. Спецификация — ТЗ «Focus Pulse» в Claude Docs.

## Как это работает

```
Чаты Telegram → бот (приём, сразу сохраняет)
             → обезличивание текста и скриншотов (правила + Tesseract)
             → каждые 20 мин: предфильтр → эпизоды → Claude → маршрутизация
             → Google Sheets → дашборд
```

- **Обезличивание** (`app/masking`). Маскируются номера карт (BIN и последние 4 цифры остаются), телефоны, счета, ПИНФЛ, паспорта, ИНН, коды из SMS, срок действия и CVV, ФИО после подписей «Получатель», «Qabul qiluvchi» и т. п. На скринах эти области закрашиваются, плюс любое слово из 8 и более цифр. Если скрин распознан неуверенно, он в Claude не уходит и помечается «не проверен». Суммы не маскируются.
- **Предфильтр** (`app/pipeline/prefilter.py`) без Claude отсекает приветствия, реакции и организационные вопросы. Сообщения со скрином или с признаками проблемы правилами не отсекаются никогда.
- **Эпизоды**: цепочка ответов, альбом или серия сообщений одного автора с паузой до 10 минут. Эпизод анализируется, когда в нём 10 минут тишины. Кнопка «Запустить анализ» разбирает всё сразу.
- **Claude** возвращает тип, раздел и операцию, платформу, приоритет, суть, шаги и совпадение с открытыми и недавно закрытыми обращениями. Ответ приходит строгим JSON через tool use.
- **Повторы** (`app/pipeline/router.py`). Закрытый баг не переоткрывается:
  - версия участника ниже версии исправления — сигнал «старая версия»;
  - версия та же или выше — новое обращение со связью «Регрессия»;
  - версия неизвестна — «Похожее — проверить».
- **Сроки** по приоритету подставляются, админ их меняет:
  - Критичный — 1 рабочий день;
  - Высокий — 3 рабочих дня;
  - Средний — дата ближайшего релиза;
  - Низкий — без срока.

## Развёртывание на Railway

1. **Google Sheets.** Создайте пустую таблицу и дайте сервисному аккаунту права редактора (можно тот же, что у QuestionsNBU_bot). Вкладки и заголовки бот создаст сам при первом запуске.
2. **Бот.**
   - В BotFather создайте бота и выполните `/setprivacy` → Disable: иначе бот не видит обычные сообщения в группах.
   - Создайте закрытый канал для обезличенных скринов, добавьте туда бота админом и возьмите ID канала (`-100…`).
3. **Railway.** New Project → Deploy from GitHub → этот репозиторий. Railway соберёт `Dockerfile`, в котором уже есть Tesseract с языками rus, uzb, uzb_cyrl. Нужна одна реплика: бот работает через polling.
4. **Переменные окружения** (Variables) — по образцу в `.env.example`:

| Переменная | Что это |
| --- | --- |
| `TELEGRAM_TOKEN` | Токен бота |
| `ADMIN_IDS` | Telegram ID администраторов через запятую. Только им бот отвечает на команды и показывает меню |
| `ADMIN_USERNAMES` | Необязательно. То же по username, например `IgorSh_Uz` |
| `DASHBOARD_OPEN_EDIT` | `1` — менять обращения на дашборде может любой, у кого есть ссылка; при первом изменении он вводит имя, оно пишется в журнал |
| `SERVICE_CHANNEL_ID` | Необязательно. Закрытый канал для обезличенных скринов; без него скрины хранятся в личке первого админа из `ADMIN_IDS` (без звука) |
| `DASHBOARD_URL` | Публичный адрес сервиса Railway (Settings → Networking → Generate Domain) |
| `SHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_JSON` | Таблица и ключ сервисного аккаунта |
| `ANTHROPIC_API_KEY`, `CLAUDE_MODEL` | Claude; по умолчанию `claude-sonnet-5-5` |
| `CLAUDE_DAILY_LIMIT` | Суточный лимит вызовов Claude, алерт при 80% (по умолчанию 2000) |
| `ANALYSIS_INTERVAL_MIN`, `EPISODE_PAUSE_MIN` | 20 и 10 минут |
| `VIEW_TOKEN` | Необязательно. Если задан, дашборд открывается только по ссылке `DASHBOARD_URL/?k=<токен>` |
| `SESSION_SECRET` | Необязательно. Секрет подписи сессий; по умолчанию выводится из токена бота |

5. **Подключение чатов.** Админ из `ADMIN_IDS` добавляет бота в действующие чаты фокус-группы — чат подключается сам. Если бота добавил кто-то другой, админ отправляет в чате `/connect`. Если privacy mode отключили уже после добавления, удалите бота из чата и добавьте снова (или сделайте его админом чата). Каналы тоже поддерживаются: бот добавляется в канал администратором; автор поста берётся из подписи («Подписывать сообщения» в настройках канала).
6. **Участникам ничего делать не нужно.** Платформу, модель телефона и версию бот берёт из их сообщений и скриншотов и запоминает в профиле участника. Повторно указывать их не нужно; более старая версия не затирает новую. `/start` и `/version` в личке бота — по желанию, для точности.
7. **Вход на дашборд.** Админ отправляет боту `/login` и получает одноразовую ссылку на 10 минут.

### Команды бота

Все команды работают только у администраторов из `ADMIN_IDS` / `ADMIN_USERNAMES`; остальным бот не отвечает, меню команд им не показывается. Список команд бот выставляет сам при запуске — в BotFather настраивать не нужно.

| Где | Команда | Действие |
| --- | --- | --- |
| Чат (админ) | `/connect`, `/disconnect` | Включить или выключить сбор сообщений |
| Личка (админ, по желанию) | `/start`, `/version X.Y.Z`, `/profile` | Уточнить свой профиль |
| Личка (админ) | `/login` | Ссылка для входа на дашборд |
| Личка (админ) | `/run` | Запустить анализ сейчас |

## Таблица

Вкладки: Messages, Issues, Links, Participants, Releases, Operations, Chats, Admins, Audit, Runs, Settings. Состав полей — раздел 10 ТЗ.

К разделу 10 в Messages добавлены поля `thread_id`, `kind`, `platform`, `device`, `screen_status`, `raw_files`, `edited_at`, а в Issues — `comment`, `authors`, `screen_unverified`.

- Значения пишутся как текст: строка из сообщения, начинающаяся с `=`, не станет формулой.
- Строки можно сортировать и фильтровать вручную: перед обновлением бот находит строку по ключу.
- Чтобы дашборд увидел ручные правки в таблице, нажмите Настройки → «Перечитать таблицу».
- В `raw_files` на несколько секунд, пока скрин обезличивается, хранится file_id оригинала в Telegram. Само изображение в таблицу не попадает, после обработки поле очищается.

## Локально

```bash
pip install -r requirements-dev.txt     # нужен tesseract с языками rus, uzb, uzb_cyrl
pytest                                  # 68 тестов
DEMO_MODE=1 python -m app.main          # демо на http://localhost:8080, вход — /auth/demo
```

Демо-режим берёт данные из выгрузки прототипа (`demo/focus_pulse_demo.xml`). Расхождения выгрузки с правилами ТЗ (раздел 16) в нём исправлены. Без `ANTHROPIC_API_KEY` классификация идёт по ключевым словам — это годится только для демо.

## Ограничения MVP

- Голосовые и видео не распознаются: попадают в «На проверке» со ссылкой на чат (этап 3).
- Праздники Узбекистана в рабочих днях не учитываются.
- История чата до добавления бота не загружается (ограничение Bot API).
- Изменения пишутся в таблицу пакетами раз в 5 секунд. При аварийном падении процесса последние секунды могут потеряться; при штатной остановке всё сохраняется.

## Обновление на Railway

Сервис на Railway запускается из готового образа `ghcr.io/igorsh0981-gif/feedback-from-sales:latest`: его собирает GitHub Actions при каждом пуше в `main` (`.github/workflows/docker.yml`). После того как сборка в Actions завершилась, в Railway → сервис → Settings → Source укажите образ с тегом нового коммита (`ghcr.io/igorsh0981-gif/feedback-from-sales:<sha>`) или `:latest` и нажмите Deploy.
